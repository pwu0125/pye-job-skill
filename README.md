# pye-job

> Spec 驱动开发的 AI 编程 Agent 工作流 skill——把想法变成可运行代码之前，先过四份递进文档。

```
spec.md（做什么）→ plan.md（怎么做）→ task.md（按什么顺序做）→ checklist.md（做对了没）
```

## 这是什么

`pye-job` 是一个安装到 AI 编程助手上的 skill（适用于支持 `SKILL.md` 约定的工具，如 ZCode、Claude Code 等）。它给 Agent 立了一条铁律：

> **HARD-GATE：获批文档全部生成之前，禁止编写任何实现代码。** 文档可以写得短，但必须存在、必须被批准。

越是「看起来简单」的任务，未被审视的假设越多，返工的概率越高——所以每个项目都走流程，流程重量随规模伸缩。

## 核心特性

- **规模分级（S/M/L）**——流程重量跟变更规模走：
  | 级别 | 场景 | 文档形态 | 审批道数 |
  |------|------|---------|---------|
  | S | 单点改动（1-3 文件、需求明确） | 一份 mini 文档 | 1 道 |
  | M（默认） | 常规功能 | 完整四份文档 | 4 道 |
  | L | 新子系统 / 跨模块 | 完整四文档 + 逐段审批 | 4+ 道 |

- **双模式**——`interactive`（人工逐道审批）/ `auto`（无人值守：闸门退化为「陈述 + 自动批准 + 决策留痕」，破坏性操作仍然必停）。

- **委派信封**——`task.md` 中每个任务自带 `Role`（人设锚定）与 `Background`（上下文信封：要读的文件、已定决策、对接接口、禁令），渲染成委派卡派给子代理，**零追问可执行**。

- **批准状态标记**——每道闸门通过的当下，在文档头部写入一行机器可读标记：
  ```markdown
  <!-- pye-job: APPROVED 2026-10-09 · spec.md · 闸门1/4 · M级 · interactive · r1 -->
  ```
  「获批」从对话记忆物化到磁盘，任何 agent（跨会话、context 压缩后、甚至别的工具）读盘即可校验 HARD-GATE，并凭标记断点续跑。

- **固定文档目录**——产出统一落项目根 `pye-job/<任务名>/` 下，随代码进版本库。

- **证据文化**——「先有证据再下结论」贯穿全程：任务验证要跑命令看输出，验收报告每条 `[x]` 必须附证据，无证据的「已完成」视为未完成。

## 工作流

```
用户想法
    │
    ▼
判定：规模分级（S/M/L）+ 会话模式（interactive/auto）+ 续跑检查（扫标记）
    │
    ▼
阶段一：需求澄清 ──→ spec.md ──→ 闸门 1（通过即写标记）
    ▼
阶段二：技术设计 ──→ plan.md ──→ 闸门 2
    ▼
阶段三：任务拆解 ──→ task.md ──→ 闸门 3（任务卡带 Role/Background）
    ▼
阶段四：验收设计 ──→ checklist.md ──→ 闸门 4
    ▼
阶段五：开发（主 Agent 自执行，或渲染委派卡派子代理并行）
    ▼
阶段六：验收（checklist 逐项验证 + 验收报告 + 决策记录）
```

## 安装

```bash
git clone https://github.com/pwu0125/pye-job-skill.git
mkdir -p ~/.agents/skills/pye-job
cp pye-job-skill/SKILL.md ~/.agents/skills/pye-job/SKILL.md
```

重启会话后生效。调用方式：

```text
显式：/pye-job 给项目加一个配置合并工具
自动：直接描述需求（「我想给 mewcode 加会话导出功能」），Agent 会主动提议走流程
```

开工后 Agent 会先报出判定结果（如「本次按 M 级 / interactive 模式执行」），可用自然语言当场调整：

- 「这单很小，按 S 级走」——降级为一份 mini 文档、一道审批
- 「无人值守跑完，最后给我报告」——切 auto 模式
- 「检测到之前的任务？从阶段三继续」——凭标记续跑

## 设计动机

Agent 编码最大的失败模式不是写错代码，而是**未被验证的假设层层复合**。pye-job 用四个机制对症下药：

1. **分层闸门**——需求→设计→执行→验收每个抽象边界放检查点，错误在最便宜的环节被拦截；
2. **持久产物**——四份文档落盘进 git，context 压缩、换会话、换执行者都不丢计划；
3. **分层验证**——每任务验证 + 行为 checklist + 端到端场景三层，配合证据规则防幻觉；
4. **防走捷径**——反模式清单直接对冲模型在「简单任务」上合理化跳过流程的行为倾向。
